# `update_planet` subcommand

Keeps the local OSM planet file fresh — downloads a new one or applies an incremental update, depending on how old it is.

```
java -jar OsmToolsBasic.jar [global options] update_planet
```

The command takes **no options of its own**. Everything is read from `app_config.yaml`.

---

## What it does

Reads the timestamp from the current planet file header (via `osmium fileinfo`) and decides:

| Planet file age | Action |
|---|---|
| > 30 days | Download a fresh planet from `planetConfig.planetLatestURL` |
| > 1 day | Incremental update via `osmupdate` (lomaps-tools Python script) |
| ≤ 1 day | Up to date — does nothing |

Downloads are staged to a `.T` temp file and atomically moved into place (optional MD5 check).

## Requires

- `osmium` on PATH (timestamp read)
- lomaps-tools Python script (`touristConfig.lomapsToolsPy`) for `osmupdate`

## Config reference

Loaded from `config/app_config.yaml` (kotlinx-serialization). Keys with a code default are optional in YAML; keys without one are required.

| Key | Req. / default | Purpose |
|---|---|---|
| `planetConfig.planetLatestPath` | required | Local planet file (input & output, in place) |
| `planetConfig.planetLatestURL` | required | Source URL for a fresh download |
| `touristConfig.lomapsToolsPy` | required | Python lomaps-tools script for `osmupdate` |

> `osmium` is **not** a YAML key — it's resolved at runtime from `$PATH`/env (`cmdConfig.osmium` lazy val), so it must be installed and on the PATH.
>
> `planetConfig` is present in the committed `app_config.yaml`.

## Example

```bash
# Update (or download) the planet file defined in app_config.yaml
java -jar OsmToolsBasic.jar update_planet

# Same, with verbose logging
java -jar OsmToolsBasic.jar -d update_planet
```

> A convenience shell script (`createPlanetUpdateShScript`) that wraps this command is generated by the Gradle build.
